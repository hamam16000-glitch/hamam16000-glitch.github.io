Editorial Standards

Last updated: November 2, 2026

Explain the actual tool

Guides describe the controls and outputs that exist on their calculator page. A page should not promise a function that is absent from its interface. Calculators with different purposes need their own examples and exclusions rather than an interchangeable explanation.

Make examples reproducible

Worked examples state enough inputs to reproduce the answer. Example prices and rates are illustrations unless a page explicitly identifies a current source and scope. No current market-price database is used by this collection.

Identify outside references

Reference links are used for defined measurement factors and relevant explanatory material. A mathematical implementation and an outside reference can use different rounding, timing or coverage assumptions; those differences should be stated instead of hidden behind a general accuracy claim.

Use dates honestly

A page’s update date records a change to that page. It is not automatically refreshed on every visit and does not imply a professional or regulatory review. When a calculation changes, its example and limitations should be checked as well.

Publish within a clear scope

The library lists 500 calculators. Documentation and calculation checks are being improved in batches; listing a tool does not imply that it has received a professional review. Each page should explain the inputs it actually accepts and identify the limits of its method.

Correct mistakes openly

Readers can report issues through Contact & corrections. Reports should include the input values and the result that seems wrong. We do not invent reviewer identities, credentials or user endorsements.
